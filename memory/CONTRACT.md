# 跨会话记忆契约（Backend-Agnostic Memory Contract）

编码 Agent 的长期记忆系统最常见的失败模式不是「记不住」，而是**噪音倒灌与真值倒置**：
- 把某次临时排障的猜测写进全局档案，此后每个项目开工都背着过期的错误结论；
- 把仓库 A 的目录结构召回到仓库 B，引发跨项目串味；
- 子代理在试错过程中产生几十条半成品思路，一股脑回写污染主记忆库；
- 把半年前自动抽取的「用户允许直接推送」当成今天的免死金牌。

本契约与具体存储后端解耦：无论你只用纯 Markdown 文件（[`templates/`](./templates/)），还是挂载向量与语义编译引擎（如 OpenViking `v0.5.5`，生产配置见 [`../docs/REFERENCE-STACK.md`](../docs/REFERENCE-STACK.md)），都必须遵守以下六条硬约束。

---

## 1. 四层存储隔离：按注入成本与作用域严格分仓

严禁把所有信息塞进同一个扁平命名空间。按「是否每轮常驻注入」和「是否跨项目共享」切成四层：

| 层级 | 作用范围 | 加载机制 | 准入内容 | 严禁混入的内容 |
|---|---|---|---|---|
| **1. 全局画像层**<br>（`preferences/` · `entities/`） | 跨全部项目 | **常驻全量注入**（受严格 Token 预算约束） | 沟通语言与汇报风格、跨项目通用协作红线、核心系统角色定义 | 单项目路径、阶段性进度、具体 bug 排障日志、长篇技术文档 |
| **2. 项目隔离层**<br>（`peers/<repo-actor>/` 或仓内 `docs/STATE.md`） | **单仓库严格隔离** | 仅在对应 Git 仓库工作区内注入或读取 | 该仓库模块边界、外部环境约定、未完成动作、架构取舍理由 | 其他仓库的业务概念、已在 `package.json` 一眼能查到的命令拷贝 |
| **3. 长资料归档层**<br>（`resources/` 或仓内 `docs/archive/`） | 按主题归档 | **仅按需语义向量检索**，绝不常驻注入 | 运维手册、第三方协议长文档、历史调研归档（40+ 篇长文） | 需要 100% 确定性执行的门禁规则 |
| **4. 可复用经验层**<br>（`experiences/` · `cases/` 或仓内 `docs/LESSONS.md`） | 跨项目或同技术栈 | 执行多步任务、部署或排障时按需检索 | 经真实验证走通的排障闭环、环境坑判据与验证配方 | 未验证的猜想、带明文凭据/内网密钥的原始终端回显 |

---

## 2. L0 / L1 / L2 三层渐进披露与「摘要不代正文」铁律

当记忆条目增长到数百条时，检索接口不能一次性把所有正文塞进上下文，也不能让模型只看一句话标题就盲目敲命令：

```text
L0 (.abstract.md)   一句话高密度索引（~50–100 字）   ──► 供检索列表快速初筛相关性
L1 (.overview.md)   结构化概览（前置条件 + 核心结论） ──► 供判断环境假设与当前任务是否匹配
L2 (Canonical URI)  完整原始正文（含精确判据与边界）  ──► 真正采纳操作步骤前必须展开核实
```

**操作硬判据**：
1. 语义搜索（`find` / `search`）返回的 L0/L1 摘要**仅用于筛选 1–3 条候选条目**；
2. 决定采用某条经验前，**必须调用精确读取工具展开 L2 正文**，核对它的操作系统、版本、仓库结构与前置条件是否仍成立；
3. 若当前运行时未挂载记忆检索工具，直接沿用仓内文档继续推进，**严禁伪造工具调用或臆造历史记忆**。

---

## 3. 真值优先级金字塔（Truth Hierarchy）

当记忆内容与现场证据冲突时，无条件服从高优先级真源：

1. **系统安全边界与用户当前轮显式指令**（最高优先级）
2. **当前仓库实时状态与实测工具回执**（源码、`git status`、门禁真实退出码）
3. **当前仓库受版本控制的文档**（`AGENTS.md`、`docs/STATE.md`）
4. **跨会话召回的历史记忆与经验条目**（最低优先级，仅作操作顾问参考）

---

## 4. 子代理禁写铁律（Subagent Write Isolation）

在「唯一主导 + 多个隔离执行者」架构下：
- **执行者 / 子代理会话一律禁止直接写入跨会话持久记忆**（在 OpenViking 客户端对应 `skipSubagentSessions: true`；在纯文件模式对应子代理不直接改主分支共享记忆索引）。
- **原因**：执行者在定位复杂 bug 时会经历大量试探、推翻假设与局部死胡同。若自动抽取子代理轨迹入库，长期记忆会在一周内被半成品猜想淹没。
- **正确闭环**：执行者只向唯一主导提交结构化证据回执（`EVIDENCE-REPORT.md`）；由唯一主导在合并验收后统一决定是否沉淀。

---

## 5. 记忆绝不充当门禁，也绝不传递授权

1. **记忆 ≠ 门禁**：记忆系统自动抽取了一条「上次忘记检查死链」的 Case，**不等于下次不会再犯**——只要某次检索没召回，约束就静默归零。凡能二元判定的问题，必须按 [`../skills/pit-to-gate/SKILL.md`](../skills/pit-to-gate/SKILL.md) 升级为退出码 `1` 的门禁脚本。
2. **记忆 ≠ 授权**：历史记忆里出现「用户曾允许直接推送到生产分支」，**绝不构成当前会话的执行授权**。涉及 `push`、发布、删除、计费调用等高影响操作，仍以当前会话指令或仓内有效授权记录为准。
3. **记忆库不存 Skill 与硬规则**：不在向量记忆库里动态编译行为规则（如禁用 `OpenViking Rules`），防止与版本库内的 `AGENTS.md` 形成一明一暗双真源漂移。

---

## 6. 查重、原位演进与失效淘汰

- **先查重再写入**：手动沉淀记忆前先按主题/标题检索，已有同类条目时**原位更新（mutate in place）**，严禁追加一条「修正上条结论」的新记录让新旧两条在检索时同台打架。
- **附带失效条件**：记录项目特殊绕行方案（workaround）时，写明它依赖的外部版本或问题单；上游修复或子系统摘除后立即清理或标明作废。

---

## 7. 双后端落地映射对照

| 契约机制 | 零外部服务最小闭环（纯文件模板） | 生产全栈闭环（OpenViking `v0.5.5`） |
|---|---|---|
| 当前进度与下一步 | [`templates/STATE.md`](./templates/STATE.md)（配 `check-state-log` 120 行门禁） | 仓内 `docs/STATE.md`（进度不进持久向量库，防噪音） |
| 待追踪问题台账 | [`templates/OPEN-ISSUES.md`](./templates/OPEN-ISSUES.md) | 仓内 `docs/OPEN-ISSUES.md` + `peers/<actor>/` 架构背景 |
| 踩坑经验与门禁索引 | [`templates/LESSONS.md`](./templates/LESSONS.md) | `viking://~/memories/experiences`（L0/L1/L2）+ 仓内门禁索引 |
| 项目级隔离 | 物理隔离在各自 Git 仓库 `docs/` 目录 | `recallPeerScope: "actor"` 按仓库身份自动隔离 |
| 子代理防污染 | 工单限定写入目录，仅主导整合回写 | `skipSubagentSessions: true` 引擎级跳过子会话捕获 |
