# 薄宿主适配

核心流程使用当前宿主实际提供的执行、派工、任务状态和消息能力。工具名、参数、调度方式、剩余派生深度和权限先核对当前运行时，不把别家接口写成必须项。

## 能力映射

| 能力 | 完整子代理宿主核对项（如 Claude Code / DSH / Antigravity） | 轻量或单会话宿主（如 Codex CLI / OpenCode） |
| --- | --- | --- |
| 执行 | 执行支路使用当前暴露的文件、搜索、Shell 与检查工具；主导只审查其回传证据 | 使用当前真实能力，不按角色机械转交 |
| 派工 | 仅在支路独立或高风险审查时检查已暴露的 Agent Teams / 子代理接口及参数 | 核对原生派工能力和剩余深度；无子代理时串行执行或跨终端会话分工 |
| 任务记账 | 双方都有共享任务工具时按真实状态机记录；没有就让负责人保留消息和文件证据，不假称已 claim/完成 | 使用仓库状态入口与实际任务机制 |
| 隔离 | 只有并行写者才优先独立 worktree + 技能内工作区检查 | 使用同一条件，不机械要求所有写入都建 worktree |
| 回报 | 有消息回传接口时由执行支路回报负责人，并核实异步唤醒约定 | 核实真实通知能力和文件交接入口 |
| 进度 | 有子代理列表或等价状态工具时做非阻塞检查 | 使用实际状态接口或检查点文件 |
| 最终检查 | 由执行者运行项目已存在的 hook/门禁并回传，不为换人重复跑同一证据；主导复核不重跑 | 核对项目真实门禁入口 |

## 交接

- 普通任务不因开发、构建、验收阶段变化而改负责人。只有派发独立支路时，才需要工单、基线和回报入口。
- 派发后主流程继续处理不依赖该结果的工作；用异步通知或状态查询接续，不做阻塞等待。执行支路完成后回报负责人，负责人仍对整合和最终交付负责。
- 其他宿主缺异步通知时，不冒充异步运行；由主导串行派单、不亲自执行，或在宿主原生状态入口可核验地推进。

## 验收层级

验收至少分开四层：①入口读回与哈希证明文件同步；②宿主刷新后的 catalog 证明发现；③新会话实际调用证明加载；④独立场景的动作日志与证据证明行为。私有技能入口不存在时，先查公共目录和宿主扫描机制，不能只凭文件存在判定可发现。历史实测状态只记在当时的本地回执里，不写进技能正文。

## 共享与刷新边界

多宿主（如 Claude Code、Codex、DSH、OpenCode、Antigravity）的技能入口应指向同一个共享实体（通过多宿主共享实体分发器如 Magpie，或自定义符号链接同步脚本）；宿主差异留在本文件，不复制整份技能。修改共享源后，运行中的会话不保证自动刷新，新会话的 catalog 与实际调用仍需单独验证；本机成功不代表其它电脑或网络远端已同步。
