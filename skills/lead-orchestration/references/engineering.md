# 工程规范

写代码、改配置、跑验证或操作 Git 之前读本文件。这里只讲怎么做对，分工与验收流程见 [SKILL.md](../SKILL.md)。

## 设计先行

- 新模块、跨层契约或重构：编码前写清目标、职责边界、依赖与数据流，设计取舍落在模块接缝与可测试性上；术语或 ADR 变化读 `domain-modeling`。
- 优先复用已有设计；出现稳定重复，或职责、隔离需求明确时才提炼抽象，不为假设需求构建通用框架。
- 目标明确就推进，可逆的常规细节自行判断；只有缺失信息实质影响目标、范围、成本或不可逆后果时才停。
- 改代码前读相邻实现，沿用同一模式。复杂历史区域先隔离边界，不在里面加新抽象或新依赖；要动它时先小步抽出可验证的接缝。

## 运行安全

- 外部输入默认不可信。涉及权限、用户数据、多租户时，在可信入口核验授权与隔离。
- 凭据不硬编码、不提交版本库、不写入日志、错误信息或未授权输出；业务确需传递时限定接收方与必要范围。
- 异步、网络或付费流程按风险明确：幂等、超时、取消、重试上限、资源释放。保留诊断上下文，不用无限重试或吞错掩盖失败。

## 测试与验证

- 写代码前写清可观察的预期行为与失败信号。能稳定复现的缺陷先取失败证据；不能复现就说明缺口，不假装测过。
- 先查现有测试是否有效覆盖，再补能挡住本次风险的最小测试。
- 预期来自需求、真实契约或独立样例，断言对外行为；避免复述实现、锁住内部结构、只证明代码变了。
- 按风险选单元、集成或 E2E；只有真实浏览器、真实服务或跨系统流程能证明的行为，才在对应环境验收。
- 复杂流程的 E2E 覆盖有代表性的失败与边界态，保留可复现的环境、输入、步骤、预期和实际；必要时附脱敏日志、截图、trace。
- 改完不只跑测试：启动目标程序或页面，走一遍主流程，看日志与真实响应；起不来时说明缺什么，不把“测试全绿”当“功能可用”。
- 接手或改动一个功能前，先有一份页面或入口、操作步骤、预期结果的清单；没有就从路由、验收记录和真实操作生成，不靠猜。
- 验证预算不少于实现预算：实现越快，越要把时间花在证明它对。
- 必要检查通过后，只为新增改动、失败或未解疑点扩大验证。文档标记、模拟结果、本地成功都不等于真实环境验收。
- 失败先分为代码、环境、测试或需求。重复错误且没有新证据时更换诊断方法；约 10 分钟只用于提醒重新判断，不是硬停或换人条件。
- 静态 fixture、脚本回归、真实宿主加载、真实业务验收分层记录，不能互相替代。

## Git 与外部操作

- 改仓库前看 `git status`、`git diff --stat` 与相关差异；保留用户和其他会话、其他 Agent 的已有改动。重叠先理解，无法安全分离或来源不明时先确认。
- worktree 盘点要拿到三个读数：相对主干领先/落后多少、工作区是否脏、是否已并入主干（`git worktree list` 只有路径与分支，缺后两项）。清理前读 `git-branch-worktree-cleanup`，保全被忽略的文件、独有数据和其他会话的资料；**Git 干净不代表可删** —— 只看 git 状态判可删的工具会漏掉被忽略的文件。
- 完整、有保存价值且通过必要验证的改动可自动本地 commit；提交前核对差异与暂存区，只含本任务内容，保留无关改动的暂存状态。探索草稿不提交。
- push、部署、发布、合并和外部写入按当前授权；缺授权先做无副作用准备，把确认放在实际操作之前。

## 文档与沉淀

- 可判定的约束优先写成测试、lint、类型检查或检查器；提示词和文档只承载不能判定的判断。
- 只保留未来会改变决策、仍有效、且不能从代码或配置低成本查到的知识。
- 任务改变既有事实时更新对应真相源。状态与待办入口只写未完成事项；过程记录归档并留链接；不复制同一事实到多处。
- 完成非平凡流程、定位真缺陷或被用户纠正后，判断是否有可复用经验：能二元判定就补测试或门禁，可复用流程更新 skill，项目事实进项目文档。判据见 `pit-to-gate`。
- 编辑或清理 skill 前读 `writing-for-agents` 与 `skill-maintenance`；只改可维护的源文件，不改生成副本或供应商缓存；验证实际加载入口，区分文件同步与运行时生效。

## 检索与临时文件

- 检索限定目录、文件和输出；避免无界扫描和重复的大包构建、复制。临时文件由创建者清理，递归删除或移动前核实绝对路径和范围。
