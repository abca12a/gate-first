# 证据回报

## 用户判断摘要（简短）

- 以前 → 现在；明确不变的边界：
- 支撑结论的关键证据与来源：
- 风险、未验证与剩余缺口：
- 本次未覆盖（逐项写没验的范围；有此项时不用“全部完成 / 收口”概括）：
- 需用户决定项（无则写“无”）：

## 原始回执与审查入口

- 工单 / 完成、检查点或阻塞 / 下一步负责人：
- 初始基线完整 HEAD / 最终完整 HEAD；非 Git 源的前后汇总哈希：
- 修改文件、diff 摘要、已有内容保留情况：
- 隔离与共享资源、权限/存储/契约/发布影响：
- 有影响的自主决定、理由及所依赖假设：

| 状态 | 实际命令（含 cwd/必要参数，本机信息留本地回执） | 退出码 | 真实输出/原资料来源 | 证明什么 | 没证明什么 |
|---|---|---|---|---|---|
| 已验证 | | | | 静态 / fixture / 协议 / 真实环境 | 未覆盖的层级或分支 |
| 待核对 | | | | 已有证据范围 | 缺少的证据和如何取得 |
| 未执行 | | 无 | 原因 | 无 | 所需环境/授权 |

- 安装文件 / 宿主发现 / 实际加载 / 行为验证分别是什么状态：
- 高风险或结论依赖关键假设时，按风险选一个能推翻它的坏例或真实读数，复用 pit-to-gate；记录输入、来源、结果与覆盖边界。适用时说明坏例失败/合法例通过；缺环境写未验证，跳过不记通过：
- 预算消耗、停止条件、失败与修正记录：
- 回退入口、用户改动保护、未验项和交给独立审查者的范围：

证据裁剪说明保留了什么、丢弃了什么；不要输出凭据、生产数据和无关配置。静态评分只能评文档契约，真实模型场景另记。独立支路回报后，仍由任务负责人审查证据并决定是否整合；负责人审查不等于已获产品验收。
