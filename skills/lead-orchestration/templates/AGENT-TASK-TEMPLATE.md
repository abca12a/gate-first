# 结果工单

短任务可把必要字段直接写在消息里。复杂、委派或独立审查任务使用本模板；没有可观察完成条件就没有可交付边界。

```text
用户结果：
- 可观察结果：
- 失败信号：
- 不改变的边界：

上下文：
- 原始需求、状态入口和证据：
- 关键待核假设：
- 现有改动与并行任务：

执行与授权：
- 一个负责人 / 确有必要的独立子任务及理由：
- 允许修改、只读、禁止触碰：
- 对象、环境、成本授权：
- 时间/调用预算、绝对截止和停止条件：
- 共享端口、账户、数据、依赖和外部副作用归属：

完成判据：
- 针对性检查、预期和失败信号：
- 项目既有最终 hook/门禁：
- 真实宿主或业务环境证据：
- 缺环境时的检查点与明确未验项：

只在需要独立写者时填写：
- 完整基线 / worktree / 独立分支：
- 工作区检查实际回执：
- 未提交依赖来源、白名单和 SHA-256：

交付：
- 已验证 / 待核对 / 未执行：
- 实际命令、退出码、关键输出和 diff：
- 实质风险、预计延误、需用户决定项：
```

工单只写本次特有内容。项目路径、构建命令、部署步骤和环境常识从现有 SOP 取，不重复抄写。实现、检查、交付可以由同一负责人连续完成，不按阶段拆单。

多个并行写者或明确的风险隔离才要求 worktree；单负责人顺序修改可直接在获授权目录工作。worktree 不隔离账户、端口、数据库、依赖链接和外部副作用，逐项指定归属。
