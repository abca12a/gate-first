# 接手项目

产出足以继续当前任务的判断：目标、已确认现状、尚缺证据、下一步及完成判据。默认在对话中简述；项目已有状态入口需要更新时写回原处，不额外生成一套报告。

## 找到入口

1. 先确认用户指向的实际仓库、分支、工作树改动和最近相关提交；相邻仓库或旧版本的记忆不能代替目标项目。保留正在进行的工作。
2. 读取适用的项目规则、README 的导航和当前状态入口，按项目规定的顺序。大文件先取标题与导航段，再定位相关章节；查根目录与明确的文档目录即可，入口不足再扩大检索。
3. 建立本轮需要的资料分工：哪里管当前任务，哪里管接口/字段/设计契约，哪里记录决策原因和历史。沿现有链接找对应章节；文件名和目录由项目决定。

完成判据：能指出下一步应该查的具体来源；只问“了解情况”时停在说明，不自动接手实现所有待办。找不到某类资料时先从相关代码或配置取证，不为凑文件名创建模板。

## 功能地图

接手后先判断项目有没有一份可执行的功能地图：用户能看到哪些页面或入口、每个入口的主操作、预期结果、谁来验。

- 没有就先建最小可执行版本，不写纯文档：路由清单做成测试（新增页面漏登记就红），主流程做成冒烟脚本（打开、操作、断言关键元素）。
- 已有路由表、导航配置或页面清单时从它派生测试，不另抄一份；地图的权威源留在代码里。
- 地图至少覆盖：入口路径、页面归属（公开/登录/控制台）、一个主操作、失败信号。失败信号必须能区分对的页面和兜底页（404、首页壳、加载中），只判字数或容器存在不算。
- 数据依赖后端的页面，本地只验“能打开、不白屏”；数据内容用真实环境或带后端的验收，不把本地通过当业务验收。
- 新增或改动页面时同步地图；地图红了先判断是页面坏了还是地图过期。

## 核对当前任务

- 用用户最新目标筛选进度和待办。区分进行中、已实现待验收、已验收、阻塞；用户指出仍在处理的事项保持可见，旧记录的日期不能单独决定归档。
- 文档是可检验的索引。只核对影响当前决策的结论：字段/单位看类型与接口证据，视觉数值看 token，执行检查看脚本和真实调用入口，发布状态看对应版本的运行证据。
- **设计目标、代码实现、测试通过、浏览器验收、生产生效分别记账。** 源码存在不证明用户链路可用；旧截图、历史“通过”和本地测试不自动证明当前版本或生产状态。
- 历史用于解释原因，研究记录用于解释选型。决定改了或相关代码/配置已变化时重验原结论；冲突保留来源与证据缺口，先做最小核对。用户决定约束目标，运行证据描述实际状态，两者不能互相冒充。
- 只加载当前任务的契约与已知坑章节；遇到多个项目、工具或宿主时分别核实。不要把某项目已停用的工作流推广为全局规则。

完成判据：能说清“要做什么、哪些已有证据、什么还没验、接下来做什么、怎么知道完成”；没有证据的部分明确待核对，不用阅读文档数量代替了解程度。

## 执行后的回写

实现或流程优化任务完成必要验证后，沿项目原有结构更新：

| 内容 | 维护位置与动作 |
|---|---|
| 未完成目标、下一步、阻塞、验收缺口 | 当前进度入口；已实现但未验收的工作继续保留 |
| 仍需追踪的缺陷或产品选择 | 已有问题清单；同步原条目状态，不再复制一份待办 |
| 接口/字段/设计契约或决策变化 | 对应事实与决策原文；注明关键条件或证据范围 |
| 完成过程、旧版本测量与停用方案 | 有复用价值的归入历史并留指针，其余压缩 |
| 跨会话记忆 | 留决定行动的短事实与条件式索引，详情在需要时读取 |

读到资料错误时，在用户授权范围内修原文并验证。只读调查则报告具体差异；接手项目本身不授权改写所有资料。

整理前核实脚本是否读取标题、表格或路径。搬移时维护相对链接、锚点和入口；运行相关已有文档检查，并实际读取任务入口，确认未完成事项没有被藏进历史。针对整套文档漂移用 `docs-drift-audit`；真实失败需要防重犯时用 `pit-to-gate`，优先更新已有约束。

完成判据：下一位能从原入口找回未完成工作、证据范围和下一步；无需先读全部历史。项目导航、消费者脚本或授权范围变化时重新判断，不沿用过期的文件映射。
