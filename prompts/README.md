# 为什么全局规则必须死守 ~30 行

许多团队在重度使用编码 Agent 三个月后，全局 `CLAUDE.md` / `AGENTS.md` 会从几十行膨胀到四五百行：每踩一个坑就往末尾补一段「严禁……」「切记……」。结果不是 Agent 变守规矩了，而是**所有规则一起失灵**。

[`instructions.template.md`](./instructions.template.md) 将全局常驻规则压缩在 **29 行（4 个一级职责块、16 条短句）**。这不是修辞洁癖，而是上下文窗口预算（Context Load）的工程算账。

---

## 1. 常驻上下文税（Context Load）的真实账本

放进全局规则文件的每一个字，都在每一轮对话、每一个项目、每一次子代理调用里无条件占用注意力预算：

| 规则体积 | 每轮固定消耗 | 实际运行后果 |
|---|---|---|
| **~30 行（仅留不变量 + 上下文指针）** | ~500–700 tokens | 四条主干红线清晰可辨；分支流程只在命中触发词时按需展开 |
| **300–600 行（混杂构建命令、历史坑点、排障清单）** | 5,000–12,000 tokens | 90% 的内容与当前任务无关；模型在长列表中部发生注意力塌陷，连最核心的「不许未授权 push」也被稀释 |

更关键的是**否定词陷阱**（Negation Trap）：在长提示词里堆叠二十条「不要做 X」，会把 X 的表征持续拉进当前上下文激活区；当上下文变长时，「不要」这一弱修饰词最先退化，禁令反而变成提示。

---

## 2. 逐段拆解：29 行里到底留了什么、踢走了什么

### 第一段：`身份与授权`（4 条）
- **留下的不变量**：输出语言与结论先行表达、授权有效域与升级条件、只读请求不改盘、凭据零落盘、外部副作用（`push`/发布/合并）必须先有授权。
- **为什么必须留全局**：这些边界在**第一条工具调用之前**就决定安全与否，来不及靠按需加载某个 Skill 再补救。

### 第二段：`执行责任`（4 条）
- **留下的不变量**：「唯一主导 + 隔离执行者」角色切分、高歧义先交最小样本、不擅自砍需求降验收、长任务明确预算与停止条件。
- **下沉出去的内容**：具体何时派子代理（「三派三不派」）、怎样开 `git worktree`、怎样写工单模板——全部压缩成**一行上下文指针**（`见 lead-orchestration`），平时零展开成本。

### 第三段：`检查与交付`（4 条）
- **留下的不变量**：以仓库规则声明的门禁为唯一准绳（钩子跑过不重跑、未接钩子手动补跑）、失败四分类（代码/环境/测试/需求）、严禁造假换绿、验收分层记账（`已验证 / 待核对 / 未执行`）。
- **下沉出去的内容**：具体的编码与测试规范通过指针下沉到 `lead-orchestration/references/engineering.md`；具体的行数上限、死链检查、密钥形状拦截**彻底移出提示词，变成 `.githooks/pre-commit` 里退出码为 `1` 的脚本**。

### 第四段：`记忆与知识`（4 条）
- **留下的不变量**：证据优先级（当前代码与仓内文档 > 外部经验召回）、记忆四层防串味边界（`preferences/entities` vs `peers` vs `resources` vs `experiences`）、查重覆盖更新、**严禁把动态编译规则或技能塞进向量记忆库**。
- **下沉出去的内容**：具体的检索参数、URI 规范与兜底逻辑下沉到 `ov-experience-memory` 与 [`../memory/CONTRACT.md`](../memory/CONTRACT.md)。

## 3. 新增一条规则前的四分流自检表

下次你想往全局提示词里加第 30 行时，先过这四问：

| 问题 | 去向 | 示例 |
|---|---|---|
| **1. 能写个脚本在违规时 `exit 1` 吗？** | 进 [`../gates/`](../gates/PROTOCOL.md) + `.githooks/pre-commit` | `STATE.md` 超 120 行、Markdown 搬移断链、未暂存文件含 `sk-` 密钥 |
| **2. 只在某类特定任务（发版、清分支、修审计单）才用得到吗？** | 进 [`../skills/`](../skills/) 对应 Skill，全局不加字或只留半行指针 | `release-and-verify`、`git-branch-worktree-cleanup`、`audit-fix-loop` |
| **3. 只对当前这一个代码仓成立吗？** | 进该仓库根目录的 `AGENTS.md` 或 `docs/STATE.md` | 本仓构建命令、目录归属、阶段性冻结说明 |
| **4. 在任何仓库、任何任务、第 1 轮对话就必须生效，且无法机器二元判定？** | **只有这一类**才有资格进 29 行全局规则，且优先合并进现有条目而非追加新行 | 外部写入授权红线、唯一主导责任制、真假验收分层汇报 |
