# 事故复盘 02：原文一字未改却静默断掉 4 条链接 + CI 53 条外部基线假死链

## 事故一：归档搬移导致相对链接基准静默偏移（2026-09-19）

- **现场**：执行文档瘦身时，将 `docs/STATE.md` 中的已完成批次原封不动剪切到 `docs/archive/STATE-2026-09.md`，并用逐行比对确认「迁出内容一字未改」。
- **漏网故障**：原文中包含 4 条形如 `[字段契约](./reference/FIELDS.md)` 的相对链接。文件从 `docs/` 移入 `docs/archive/` 后，**目录层级深了一层**，`./reference/FIELDS.md` 被解析成不存在的 `docs/archive/reference/FIELDS.md`。因为正文字符完全一致，人工 code review 与 `diff` 比对全部放行，4 条链接静默失效。
- **教训**：文档搬移的验收必须拆成两条独立判据——① **内容保真**（逐行一致）；② **引用可达**（按新位置重解析全部相对链接与 `#anchor` 标题锚点）。

## 事故二：干净 CI 环境把 53 条跨仓库基线引用误判成死链（同日复盘）

- **现场**：门禁脚本初版上线后本机全绿，推上 GitHub Actions 后瞬间报 **53 条死链失败**。
- **根因**：迁移对照文档中引用了本机相邻只读旧仓库的绝对路径与源码行号（如 `/path/to/legacy-web-console/src/router.tsx:155`）。开发机上该目录存在因此通过；干净的 Linux CI runner 上根本没有那棵外部 Git 树，初版脚本把「环境未挂载外部基线」当成了「文档写错路径」。
- **精准修法（不靠粗暴关闭检查）**：
  1. 剥离路径末尾的 `:行号` 标注；
  2. 对跨仓库绝对路径，先向上回溯父目录查找 `.git`（确认这棵外部基准工作树在当前机器上是否已挂载）：
     - 若外部工作树**已挂载**但目标文件不存在 → 属于真实的源码重命名/漂移，**判失败（`exit 1`）**；
     - 若整棵外部工作树**未挂载**（如干净 CI runner） → 不伪造失败，但在输出中显式统计并打印 `外部基线不可用，未校验 N 条`，严格区分「已验通过」与「环境未挂载」。
  3. 仓库内相对路径与 Markdown `#anchor`（含重复标题的 `-1`、`-2` 后缀）在任何环境下**始终 100% 强校验**。
  4. 剥离围栏代码块与行内反引号代码段，避免文档中用反引号包裹的反面语法示例触发误报。
