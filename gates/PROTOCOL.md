# 门禁自增长工程协议（Gate Self-Growth Protocol）

在多会话、多宿主的 AI 辅助工程中，**自然语言规则随时间推移必然经历注意力稀释**。只要一条规则违反后代码照跑、测试照绿、命令退出码为 `0`，它迟早会被某个聚焦于当前任务的 Agent 绕过。

本协议定义如何把一次真实事故或反复返工，转化为一条**跨宿主确定性拦截、自带好坏对照、不会静默腐烂**的机器门禁。生成或演进门禁的操作步骤见 [`skills/pit-to-gate/SKILL.md`](../skills/pit-to-gate/SKILL.md)。

---

## 1. 经验分流三判据：不是所有问题都该写进提示词

每次修完真实缺陷、经历返工或被用户纠正后，先查现有载体，再按下表路由，**严禁把机器能判定的约束继续堆回全局提示词**：

| 判定问题 | 目标载体 | 完成判据 |
|---|---|---|
| 能否把输入、预期与失败信号编码成确定性程序，稳定做二元判定？ | **机器门禁 / 回归测试**（接入 `.githooks/pre-commit` 或 CI） | 已知坏例退出 `1`、合法例退出 `0`，真实提交入口会阻断违规 |
| 仍需上下文判断，但取证步骤、决策分支与停止条件可跨项目复用？ | **工作流 Skill**（`skills/<name>/SKILL.md`） | 触发指针清晰，步骤无宿主硬绑定，产物附可核验回执 |
| 属于当前项目的架构事实、字段契约、例外理由或设计取舍？ | **仓内文档 / 项目级记忆**（`docs/` 或项目 `peers` 记忆） | 写清结论、原因、影响面与失效条件，不复制配置即可查到的事实 |

> **硬边界**：长期记忆系统自动抽取的案例（`Case` / `Experience`）只算**语义召回参考**，不是门禁。未召回即等于不存在；要防复发，二元可判问题必须下沉为非零退出的检查器。

---

## 2. 铁律一：「只提醒不失败」（`exit 0`）不等于门禁

警告日志对自动化流水线和长上下文 Agent 几乎没有阻断力：

- **实测复盘**（详见 [`examples/01-state-log-cap/INCIDENT.md`](examples/01-state-log-cap/INCIDENT.md)）：某仓库的状态读取脚本从 2026-09-17 起在章节超过 `120` 行时打印黄色警告，同一条上限同时写在三份核心文档里，但脚本**退出码为 `0`**。仅仅 8 天后（2026-09-25），该节膨胀至 **569 行 / 104 KB**，每次开工向模型上下文倾倒上百 KB 历史日志，全程没有任何步骤报错。
- **职责分离原则**：不要给「供人或 Agent 读取状态的命令」强行加上非零退出（那会在状态超标时连读取入口一起堵死）。正确做法是：
  1. 读取工具继续负责输出内容；
  2. 独立建立门禁脚本（如 `check-state-log.mjs`），超限立即向 `stderr` 打印搬移指引并 **`exit 1`**；
  3. 两者通过共享模块引用**唯一阈值源**。

---

## 3. 铁律二：单一阈值源（Single Source of Threshold）

当一个边界同时被「展示工具」和「门禁脚本」消费时，如果在两个文件里各自写一遍 `const LINE_LIMIT = 120`，迟早会演变成「A 报超限、B 判通过」，且两边各自测试全绿。

- 将章节标题、行数上限与切片函数抽入纯模块（如 [`examples/01-state-log-cap/state-section.mjs`](examples/01-state-log-cap/state-section.mjs)），导入时零副作用。
- 在阳性对照测试中加入**源码级同源断言**：检查门禁与读取脚本均从共享模块导入常量，且不出现独立的阈值字面量定义。

---

## 4. 铁律三：阳性对照双轨法（Positive Control）

**一条从未见过它变红的门禁，与恒返回 `0` 的空脚本在输出上完全同形。** 所有门禁落地时必须验证两条轨道：

### 轨道 A：隔离夹具对照（测试判定逻辑与边界）

在系统临时目录（`os.tmpdir()`）构造最小可复现目录或临时子 Git 仓库，自动覆盖：
1. **阴性对照（合法例）**：贴近上限边界的合法输入（如恰好 `120` 行、合法同目录链接、带理由登记的测试桩），断言退出码为 `0`；
2. **阳性对照（违规坏例）**：最小违规输入（如 `121` 行、搬移后断链、未 `git add` 的新文件含假密钥），断言退出码为 `1` **且错误输出精确命中违规原因**；
3. **运行完自动清理**：在 `finally` 块中删除临时夹具，不污染工作区。

### 轨道 B：真实入口注入对照（测试扫描范围与接线）

纯函数单测或临时夹具证明不了「真实仓库的目标文件没有被路径过滤规则漏掉」：
1. 向真实目标范围临时注入一处最小违规（或临时把被测实现退回缺陷版）；
2. 运行项目声明的**真实总门禁入口**（如 `node scripts/check-all.mjs`），确认整条链路返回非零退出码；
3. 还原文件并核对 `git status` / `git diff`，复跑确认回到 `exit 0`。

> **警惕假阳性对照**：还原旧代码做对照时，必须忠实还原**调用点语义**，不能只替换条件表达式而把分支动作写反。若还原后测试依然全绿，第一反应应怀疑对照写错，而不是宣布「该改动无需测试」。

## 5. 两种高频「假绿」反模式

### 反模式 1：自证循环（Expected Value Derived from Implementation）

测试用被测公式反推预期常量（例如用 `售价 / 1.4 / 7.2` 算成本，再断言 `售价 >= 成本 * 1.15`，代数化简后恒等于 `1.344 >= 1.15`），导致把业务加价逻辑删成 `0` 后测试依然全绿。

- **破局判据**：预期值必须来自独立真源（手算常数、外部协议样本、固定快照）；把核心实现临时改成 no-op 时测试必须变红。

### 反模式 2：绕过真实调用链（Bypassing Pre-Steps / Scan Scope）

线上入口先执行归一化再执行校验（导致非法值被静默转成合法默认值），而测试直接调用底层校验函数，得出「非法值会被拦截」的假结论；或者密钥门禁只用 `git ls-files`（只看暂存区索引），漏掉了刚创建但尚未 `git add` 的新文件（详见 [`examples/03-secret-shapes/INCIDENT.md`](examples/03-secret-shapes/INCIDENT.md)）。

- **破局判据**：门禁扫描范围必须对齐「最终会被提交或上线的工作树集合」（如 `git ls-files -z --cached --others --exclude-standard`），至少一条对照必须穿过真实 CLI 子进程入口。

## 6. 三态退出码规范（`0 / 1 / 2`）

所有门禁脚本统一遵守三态退出码，严禁混用：

| 退出码 | 含义 | 典型场景 | 后续动作 |
|---|---|---|---|
| **`0`** | **验证通过** | 扫描完成且未发现违规（外部可选基线未挂载时须在输出中显式写明「未校验 N 条」，不冒充已验） | 允许提交或继续流水线 |
| **`1`** | **规则违规** | 超行数上限、存在断链/坏锚点、发现未登记凭据形状、白名单条目过期、发现私人信息泄漏 | 阻断提交；修复资产或按规登记豁免 |
| **`2`** | **运行错误** | 命令行参数错误、目标根目录不存在、运行时异常、缺少必需解释器 | 阻断提交；先修检查器或环境，不把门禁崩溃误读为业务违规 |

> **Git Hook 铁律**：在 [`.githooks/pre-commit`](hooks/pre-commit) 中，当找不到 `node` 或找不到门禁入口脚本时，必须 **`exit 1`** 拦下提交，绝不能 `exit 0` 静默放行——否则「门禁根本没跑」会被协作规则误记为「提交钩子已验过」。

---

## 7. 豁免与白名单防腐烂规则

确需在测试桩或文档中保留形似违规的样本时：
1. **无理由不准入**：白名单结构必须是 `Record<字面量, 非空理由说明>`，不允许纯数组；
2. **双向过期反查**：门禁每次扫描完统计白名单命中次数；若某条白名单在全仓已不再出现，立即报「白名单过期」并 **`exit 1`**（见 [`examples/03-secret-shapes/check-secret-shapes.mjs`](examples/03-secret-shapes/check-secret-shapes.mjs)），防止白名单退化成无人清理的藏污纳垢区。

---

## 8. 门禁挂载点选择：Git Hooks 为主，宿主 Hook 为辅

1. **主挂载点（必选）：Git `core.hooksPath`（`.githooks/pre-commit`）**
   - 跨宿主绝对一致：无论代码由 Claude Code、Codex、DSH、OpenCode、Antigravity 还是人工编写，只要执行 `git commit` 就必然经过同一道关卡。
   - 注意两处物理细节：① 钩子文件必须在 `.gitattributes` 钉死 `eol=lf`（防 Linux/macOS 因 `#!/bin/sh\r` 坏解释器失败）；② 执行门禁前必须 `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE GIT_PREFIX GIT_OBJECT_DIRECTORY GIT_COMMON_DIR`，防止外层 Git 环境变量污染门禁内部的子仓库回归测试。
2. **辅挂载点（可选）：宿主生命周期 Hook（如 [`hooks/stop-hook-example.mjs`](hooks/stop-hook-example.mjs)）**
   - 在支持会话收尾钩子的宿主上提前拦截未过门禁的交付，但必须实现**重入死循环保护**（检查 `stop_hook_active` 与最大重试次数上限）。
